# 制作・編集の共通原則

更新日：2026-11-16

1. **一次情報へ戻れること。** 商品の事実は公式商品・工房・販売店の資料、技法の一般説明は適切な公式資料で確認する。出典URL・実際の確認日・支える主張を `docs/research/sources.json` に残す。検索抜粋だけで確定しない。
2. **知らないことを埋めないこと。** 重量・金具・製造地等の不明値は `null` または明示的な未確認表記とする。販売店住所を製造地にしない。技法の国指定を個別商品の認証へ転用しない。未確認属性はフィルター条件を満たさない。
3. **独自の編集価値を加えること。** 説明の翻訳転載で終わらず、選ぶ理由・用途の提案・比較軸・確認点を示す。実物未使用の現状で使用体験、快適性、独自評価、レビュー、推薦実績を作らない。
4. **画像の公開と許諾を別に考えること。** 公式サイトの写真も許諾なしでは取得・掲載しない。出典表記は許諾の代わりではない。画像台帳へ権利者・許諾根拠・範囲・日付を残す。初期版の自作CSS抽象装飾に加え、003のユーザー依頼によるAI着用イメージを使える。ユーザー最新指示007に従い、常時見える短いAIイメージ/AI image表示を付け、商品写真・金具/寸法の証拠として扱わない。
5. **編集情報と広告状態を分離すること。** 商品・販売店・広告プログラム・商品別リンクをIDで関連付ける。プログラムと商品リンクの両方が `approved`、programIdあり、有効HTTPSの承認済みURLあり、確認日ありの場合だけ広告リンクを使う。それ以外は通常URLへ戻し、通常URLもなければCTAを出さない。
6. **関係を明瞭に開示すること。** 最初の広告リンクより前に現状に合う開示を置く。広告リンクは `rel="sponsored"` を含める。架空の広告ID・追跡URL・申請状態は公開データへ入れない。停止時も設定変更のみで通常リンクへ戻せることを維持する。
7. **販売者と誤認させないこと。** 当サイトに注文・決済・発送はない。公開UIでは販売手順・責任説明を繰り返さず、紹介に集中する。内部の事実管理では価格・在庫・税金・送料・返品を商品/販売店に分ける。海外配送は対象国と商品別の条件を区別し、英語ページの存在から世界配送を推定しない。
8. **個人情報を作らないこと。** 未提供の氏名・住所・メール・資格・経歴を推測しない。最新のユーザー指示によりお問い合わせは設けず、架空の窓口を作らない。技術公開の条件と、提携先が個別に求める申請情報を区別して記録する。
9. **仕様と実装を同時に直すこと。** 仕様→影響範囲→変更→必要な検証→記録の順を守る。大きな機能は新しい仕様ディレクトリ、小さな修正は該当仕様と変更履歴で扱う。安定IDや公開slugは理由なく変えない。
10. **実行したことだけを完了とすること。** ビルド、画面確認、公開、申請送信、提携承認を分けて報告する。未計測の性能点数、検索流入、売上、審査合格を保証しない。未調査の空地域ページを公開しない。
