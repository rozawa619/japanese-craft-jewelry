# SORA TikTok動画 制作仕様（SDD）

版: 1.4 / 最終更新: 2026-11-22（神奈川優先シリーズ運用を追記）
対象: `SORA｜旅先で待ち合わせ` の日本の工芸アクセサリー紹介×一人称デート動画。

## 目的と世界観

- 視聴者が旅先で日本人女性と待ち合わせ、恋人目線で会話しているような **boyfriend POV**。
- 日本の伝統工芸・ものづくりを、女性が身に着けたアクセサリーから自然に知る。
- 最初は神奈川（箱根・鎌倉など）、将来は全国47都道府県。**箱根だけに限定しない**。
- 商品・地域ごとにサイトに掲載された **別の成人女性** を使う。全作品で同じ一人の女性を使い回す仕様ではない。
- 動画は架空人物のAI生成イメージ。実物の試着・レビュー・商品仕様を証明する表現にしない。サイトへ誘導するが実提携済みと偽らない。

## 当面の連載範囲（2026-11-22 更新）

- ユーザー指定により**当面は神奈川県シリーズを優先**。神奈川県内なら箱根・鎌倉など地域を変えてよい。全国展開の構想は保持するが、ユーザーが切り替えるまで神奈川県外の新作を勝手に提案しない。
- 毎話、現行サイトの公開済み神奈川商品と対応する人物画像を確認し、進行中の話・次の候補を`production-status.json`に登録する。候補の事前選定と動画完成を区別する。
- 現在のもみじブローチ編の次は**陽雅堂の椿ペンダント**。正本は`docs/video/episodes/kanagawa-yogado-kamakura-bori-camellia-pendant.md`。現在の編を無断で完成扱いにして次へ飛ばない。

## 絶対に維持する制約

1. **サイトの該当商品ページに載っている着用女性の画像を唯一の人物参照とする**。別の女性を文章から新規生成して代用しない。顔立ち、目鼻口の形、輪郭、肌の特徴、前髪・髪型など**本人を見分ける特徴を最優先で維持**する。服装を変えてほしいとの依頼なら**変更対象は服装だけ**とし、顔や人物そのものを作り直さない。動画向けの縦9:16の派生開始画像を必要とする場合は、元画像からの編集に限定し、採用前に元画像と横並びで目視照合。別人に見えた画像は破棄し、サイト画像を無断で上書きしない。
2. 商品は現行の `src/data/catalog.json` にある公開商品から選ぶ。商品IDと `src/data/editorial-images.json` の対応を確認する。創作の商品と未掲載商品をサイト掲載済みのように紹介しない。
3. **Google Flow / Video → Frames（開始フレーム）**を基本とする。基本は **縦9:16 / 10秒（選択可能な場合）/ 1クリップずつ**。実際のモデル・尺・解像度はUIで確認して台帳に記録する。従来の360pは過去設定であり全モデルで保証しない。
4. 女性は **カメラの向こうの視聴者に自然な日本語で話しかける**。親しみやすい優しい笑顔。画像→動画では開始画像に人物/服装/背景が入っているので、**プロンプトは主に1つの小さな動作とカメラ**に集中し、人物の特徴や禁止事項を反復しない。
5. **日本語音声の読み間違い対策**：短い1文で、話者を指定して日本語で発話させる。読みを固定する必要がある場合はセリフをひらがな中心にし、漢字・ローマ字・意味の英文を同じ生成プロンプトに何度も載せない。外来語の誤読が起きたら自然な日本語に言い換える。自然な標準日本語の抑揚・言い切り・口の動きを採点。Google Cloudの「話者 says: 発話内容」形式も試す（必ず成功するとは限らない）。音声が繰り返し崩れたら無音動画＋後編集で日本語音声を付ける方法へ切り替える。
6. 原則、10秒の構成は **0–2秒 視線と微笑み → 2–7秒 会話と装身具 → 7–10秒 恋人へ問いかけた余韻**。無理に長文を詰め込まず、最後まで自然に言い切れる長さにする。
7. Flowでは **日本語・英語字幕、見出し、ロゴ、BGM、CTAテキストを生成しない**。日本語・英語字幕、商品名、BGM、サイト導線はCapCut等で後編集。環境音は控えめ。
8. POV・自然光・リアル寄りの映像。手首のアクセサリーなら **顔＋装飾のある片手首** を見せ、反対の腕は最初から構図外にする。片手首に1本なら全フレームで1本。**両手首が写る開始画像や、片方の手首を動かして見せる動作は避け、腕は安定させる**。否定命令の長大な羅列より、見せる構図を肯定文で指定し、負例は簡潔なキーワードにとどめる。
9. 商品形状はモデルAIの再現の限界があるため、実物そのものとして保証しない。公式画像の無断転載、生成入力への無許可流用、虚偽のアフィリエイト表示を避ける。



## 人物同一性ロック・着替え編集（2026-11-21追加）

- **入力の原則**：`editorial-images.json`が示す現行サイトの実際の女性画像を編集ツールに読み込む。**文章だけで「同じ雰囲気の若い女性」を描き直すのは不可**。動画からの切り出しも元画像と顔が一致するか検査する。
- **保持するもの**：顔の輪郭、目と眉の形・位置、鼻、口、顔の比率、既存の肌・髪・前髪の特徴、同じ成人女性だと識別できる外観、そして該当商品1点の形・位置。
- **変更を許可するもの**：ユーザーが希望した服装の色・デザイン・シルエット、および必要な縦9:16構図と背景の微調整のみ。ユーザーの明示依頼なしに顔・髪型・体格を大幅に美化/若返り/変更しない。
- **推奨する編集の順序**：(1) 既存画像を表示・比較 (2) 服装だけを局所編集 (3) 元の顔と編集後の顔を横並び比較 (4) ブレスレットが1個か、片方の手首にだけあるか検査 (5) 問題がある場合は不採用・再編集。新たな「別モデル」を生成して置き換えない。
- **品質ゲート**：顔が別人に見える、ブレスレットが増殖、商品や服が不自然に破綻、いずれかがあれば**不採用**。画像をユーザーに見せる際は、あくまで編集候補であり元の女性との一致が保証されたと断言しない。
- **禁止する近道**：「可愛くして」という曖昧な指示だけで全身再生成しない。**同じ女性の服だけを今風に**と明確に指定し、編集画像にその人物の実際の参照を使用する。

## 画像→動画の制作ゲート（Google公式の推奨＋SORA独自の検証方針）

[調査と一次出典](research/flow-veo-prompting-2026-11-21.md)に根拠を記録。

1. **画像プリフライト**：元サイト画像を確認し、顔・商品・手首の数が明確か判定。元画像が横長（例: 1536×1024）で9:16へ動画化するなら、商品を見切らない範囲で縦型の**動画専用派生**を検討。派生は元画像とは別ファイル・別IDで記録してから使う。静止画で両腕に同じ商品があるものは動画化しない。
2. **動きは1つだけ**：基本は「顔に視線を向け微笑む」、ブレスレット着用腕は体の横/胸付近で静止、反対腕はフレーム外。カメラは固定か極小の動き。多段階ジェスチャーを避ける。
3. **短いプロンプト**：開始画像が示す人物・背景・衣装を延々と再説明しない。構図・微細な動き・短いセリフの3要素で十分な場合は短いプロンプトを選ぶ。
4. **一度に1変数を試す**：開始画像変更、動作変更、音声変更を同時に実施して原因を断定しない。A/Bを残し、再生成に使った正確な画像・指示・モデルを記録。
5. **失敗からの切替**：腕やアクセサリー重複が2度続けば「No duplicate」を増やすのでなく開始画像と構図を変える。発音失敗が続けば短文1行へ、なおダメなら Flow project Settings の **Return silent videos** で映像のみ生成してCapCut等で別音声を付ける。別音声ではリップシンクは別工程。
6. **声の参照**：Flowの **Omni Flash / Ingredients** で音声参照を利用できる場合がある。画像→動画のすべてのモデルで声参照可能とは扱わない。対応を画面で確認する。

## クリップと総集編

- **Flow 1本は10秒**。以前の箱根編は約60秒の1本へ編集する構想で、複数クリップを組み合わせる。60秒完成・公開の証拠がなければ完了扱いにしない。
- Flow素材は1本ずつ採点・修正。動画や再生成の完成状況は `production-status.json` に記録する。
- 後編集で日英字幕/音楽を付与し、商品ページへ誘導。外部SNSの投稿は本人が行った/投稿URLを確認した場合のみpublished。

## 受入基準（1クリップ）

- [ ] 開始画像が現在の対象商品に紐づいている。動画専用派生なら元画像・別ファイル/差分・画像検査結果を記録した
- [ ] 元画像と編集画像を横並びで比較し、**顔が同一人物と確認できる**。服の変更を依頼された場合も顔・髪の特徴は維持されている
- [ ] 縦9:16、約10秒、boyfriend POV
- [ ] 日本語が正しく発音され、ネイティブらしい抑揚・口パク。単語の欠落や末尾切れがない
- [ ] 腕・指・顔・宝飾品に目立つ崩れがない。左右両手首のアクセサリー数を全フレームで確認した。ブレスレットは終始1本のみ
- [ ] Flow出力に不要な文字・音楽・追加人物がない
- [ ] 何を見せたいか（工芸とジュエリー）が伝わる
- [ ] 不合格なら問題と再生成指示を記録してからやり直す。同種の重複が続けば開始画像を変え、発音不良が続けば無音・別録り案に移行する

## 変更管理

明示指示による「決定変更」はこの仕様の版を上げ、エピソードで何を変えたかを記す。単一動画の特殊演出は該当episodeにだけ記録。**過去の承認済みプロンプトを、別チャットで勝手に要約/意訳しない**。
