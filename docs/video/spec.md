# SORA 動画制作と投稿文の仕様（SDD）

版 1.13（2026-11-25更新、縦の開始画角の事前確認と肌の採用基準を明確化）
対象は `SORA｜旅先で待ち合わせ` の日本の工芸アクセサリー紹介×一人称デート動画と、TikTok・Instagramの投稿文。

## 目的と世界観

- 視聴者が旅先で日本人女性と待ち合わせ、恋人目線で会話しているような **boyfriend POV**。
- 日本の伝統工芸・ものづくりを、女性が身に着けたアクセサリーから自然に知る。
- 最初は神奈川（箱根・鎌倉など）、将来は全国47都道府県。**箱根だけに限定しない**。
- 商品・地域ごとにサイトに掲載された **別の成人女性** を使う。全作品で同じ一人の女性を使い回す仕様ではない。
- 動画は架空人物のAI生成イメージ。実物の試着・レビュー・商品仕様を証明する表現にしない。サイトへ誘導するが実提携済みと偽らない。

## 当面の連載範囲（2026-11-22 最新）

- **神奈川シリーズは概ね一巡**。サイトの公開8商品中7商品はTikTok公開を確認した。残るDahliacyan オレンジムーンストーンの透かし彫りピアスは制作済みで投稿未確認。重複回避のため8商品とも新作候補から外し、次の地域の候補は制作台帳を参照する。
- **京都府シリーズを開始**。対象はサイト公開7商品と対応する女性元画像7点。着手状況は[京都編の台帳](kyoto-series-plan.json)と[制作台帳](production-status.json)を参照する。
- **新しいチャットでの入口**：[完全引継ぎ書](NEW_CHAT_HANDOFF.md) → この仕様 → [制作状況](production-status.json) → [TikTok重複防止台帳](tiktok-publication-registry.json) → 次シリーズ候補。最新の `catalog.json` と `editorial-images.json` で公開商品と人物原本を毎回照合。
- 毎話、現行サイトの公開商品と対応する人物画像を確認し、進行中の話・次の候補を`production-status.json`に登録する。候補の事前選定と動画完成を区別する。

## 画像の提供方法 — 現在の標準運用（2026-11-22 ユーザー指定）

- **次からはユーザーが「次の動画」「次の女性」と依頼したら、最初にサイトで使っている元の着用女性画像をそのまま提示する。** 商品IDと `src/data/editorial-images.json` の画像パスを照合し、正本画像のプレビュー／直接リンクと商品ページを示す。
- **開始画像の新規AI生成、服の変更、顔の補正、9:16の切り出し、Canvaデザイン作成などは標準で行わない。** ユーザーがその加工を明示的に頼んだ場合のみ、元画像を保管して別ファイルとして実施する。
- Google Flowにはサイト掲載の元画像を直接アップロードしてもらう。横長の元画像では、[冒頭の見切れを防ぐ手順](#冒頭の見切れを防ぐ手順)に沿って縦構図を確認する。
- 動画用プロンプトはユーザーが求めた場合に併せて用意する。元画像をFramesの開始フレームかIngredientsの参照に使い、**サイト女性とアクセサリーの同一性を保つ**。
- 過去の「縦9:16開始画像を必ず先に作る」旨の手順は、ユーザーの新しい方針により**任意の例外対応**へ変更する。

## TikTok公開動画との照合・重複防止（2026-11-22 追加）

- 投稿先は **[SORA TikTok](https://www.tiktok.com/@soracraftdiary)**。投稿別の証拠と照合結果の正本は [`tiktok-publication-registry.json`](tiktok-publication-registry.json)。**このファイルを制作台帳とサイト商品マスタと一緒に、毎回の新作提案前に読む**。
- **重複判定キーを2つ使用**：商品ID (`catalog.json` の `id`) と、サイト女性の元画像 `editorial-images.json` の `assetId` / `path`。女性とアクセサリーを同時に重複させないだけでなく、同一女性の別商品バリエーションにも注意。ユーザーが明示的に別案・再制作を希望しない限り、一度使った／予約済みのサイト女性や商品を新作の候補にしない。
- **神奈川の既存8点を除外**。公開7商品と制作済み・投稿未確認の1商品、および各商品に紐づく女性画像を新作の重複照合に使う。 [TikTok公開台帳](tiktok-publication-registry.json)
- **販売店の寄木4点**：箱根丸山物産の `maruyama-clip-c/pierced-c` は同じ女性画像、`maruyama-clip-d/pierced-d` も同じ女性画像。片方を使ったらもう片方の女性として新規提案しない。県IDが空欄なので神奈川製の商品とは断定しない。
- `idea`、`prompt_ready`、`generated_unreviewed`、ユーザー申告、`published` は区別する。公開を確認できる投稿URLと内容の照合を台帳に残す。公開欄のキャプションとサムネイルで照合した場合は、全編・音声と開始画像の確認範囲も記録する。
- **TikTokをチェックできない時**：アカウントが空だと推測しない。事実として「一覧取得不可」と台帳へ記録し、既存の完成物候補を再提案しない。ユーザーの投稿URL一覧や、接続済みのSNS管理サービスから公開投稿の一覧を取得できた場合には、キャプション・サムネイル・動画から1件ずつ製品/人物と照合して更新する。
- **新作の前チェック手順**：①公開サイトに商品と女性画像がある ② `tiktok-publication-registry.json` に商品ID・人物画像が未使用か ③ `production-status.json` に過去の動画/指示文の履歴がないか ④ 候補なら新規 episode を記録。前の候補が `prompt_ready` でも新しく同じ女性を薦めない。
- **外部SNSを直接読めない場合**：これは外部の閲覧制限であり、GitHubの一覧がTikTokの公開一覧と同等だと主張しない。

## 絶対に維持する制約

1. **サイトの該当商品ページに載っている着用女性の画像をそのまま使用し、唯一の人物参照とする**。別の女性を文章から新規生成して代用しない。顔立ち、目鼻口の形、輪郭、肌の特徴、前髪・髪型など**本人を見分ける特徴を最優先で維持**する。服装を変えてほしいとの依頼なら**変更対象は服装だけ**とし、顔や人物そのものを作り直さない。ユーザーが縦9:16への加工を明示的に依頼した場合のみ、元画像からの編集に限定し、採用前に元画像と横並びで目視照合。別人に見えた画像は破棄し、サイト画像を無断で上書きしない。
2. 商品は現行の `src/data/catalog.json` にある公開商品から選ぶ。商品IDと `src/data/editorial-images.json` の対応を確認する。創作の商品と未掲載商品をサイト掲載済みのように紹介しない。
3. **Google Flowは縦9:16、10秒（選択可能な場合）、1クリップずつ**。[冒頭の見切れを防ぐ手順](#冒頭の見切れを防ぐ手順)に沿ってFramesまたはIngredientsを選ぶ。実際のモード・モデル・尺・解像度を確認して台帳に記録する。従来の360pは過去設定であり全モデルで保証しない。
4. 女性は **カメラの向こうの視聴者に自然な日本語で話しかける**。親しみやすい優しい笑顔。画像→動画では開始画像に人物/服装/背景が入っているので、**プロンプトは主に1つの小さな動作とカメラ**に集中し、人物の特徴や禁止事項を反復しない。
5. **日本語音声の読み間違い対策**：短い1文で、話者を指定して日本語で発話させる。読みを固定する必要がある場合はセリフをひらがな中心にし、漢字・ローマ字・意味の英文を同じ生成プロンプトに何度も載せない。外来語の誤読が起きたら自然な日本語に言い換える。自然な標準日本語の抑揚・言い切り・口の動きを採点。Google Cloudの「話者 says: 発話内容」形式も試す（必ず成功するとは限らない）。音声が繰り返し崩れたら無音動画＋後編集で日本語音声を付ける方法へ切り替える。
6. 原則、10秒の構成は **0–2秒 顔と装身具を同時に見せ、視線と微笑み → 2–7秒 会話 → 7–10秒 恋人へ問いかけた余韻**。無理に長文を詰め込まず、最後まで自然に言い切れる長さにする。
7. Flowでは **日本語・英語字幕、見出し、ロゴ、BGM、CTAテキストを生成しない**。日本語・英語字幕、商品名、BGM、サイト導線はCapCut等で後編集。環境音は控えめ。
8. POV・自然光・リアル寄りの映像。手首のアクセサリーなら **顔＋装飾のある片手首** を見せ、反対の腕は最初から構図外にする。片手首に1本なら全フレームで1本。**両手首が写る開始画像や、片方の手首を動かして見せる動作は避け、腕は安定させる**。否定命令の長大な羅列より、見せる構図を肯定文で指定し、負例は簡潔なキーワードにとどめる。
9. 商品形状はモデルAIの再現の限界があるため、実物そのものとして保証しない。公式画像の無断転載、生成入力への無許可流用、虚偽のアフィリエイト表示を避ける。



## 人物同一性ロック・着替え編集（2026-11-21追加）

- **入力の原則**：`editorial-images.json`が示す現行サイトの実際の女性画像を編集ツールに読み込む。**文章だけで「同じ雰囲気の若い女性」を描き直すのは不可**。動画からの切り出しも元画像と顔が一致するか検査する。
- **保持するもの**：顔の輪郭、目と眉の形・位置、鼻、口、顔の比率、既存の肌・髪・前髪の特徴、同じ成人女性だと識別できる外観、そして該当商品1点の形・位置。
- **変更を許可するもの**：ユーザーが希望した服装の色・デザイン・シルエット、および必要な縦9:16構図と背景の微調整のみ。ユーザーの明示依頼なしに顔・髪型・体格を大幅に美化/若返り/変更しない。
- **推奨する編集の順序**：(1) 既存画像を表示・比較 (2) 服装だけを局所編集 (3) 元の顔と編集後の顔を横並び比較 (4) ブレスレットが1個か、片方の手首にだけあるか検査 (5) 問題がある場合は不採用・再編集。新たな「別モデル」を生成して置き換えない。
- **品質ゲート**：顔が別人に見える、ブレスレットが増殖、商品や服が不自然に破綻、いずれかがあれば**不採用**。画像をユーザーに見せる際は、あくまで編集候補であり元の女性との一致が保証されたと断言しない。
- **禁止する近道**：「可愛くして」という曖昧な指示だけで全身再生成しない。**同じ女性の服だけを今風に**と明確に指定し、編集画像にその人物の実際の参照を使用する。

## 動画の肌と表情

- サイト原本の顔立ち・髪型・肌色を保つ。柔らかく均一な光と自然な肌のキメで、やさしい目線と小さな微笑みを見せる。
- **頬・口元まわり・あごに見えるほくろや単独の濃い点があれば要修正**。新作選定では、こうした点が目立たない原本を優先する。
- Flow指示文の肌の段落で、ほくろと濃い点が見えない状態を明記する。元画像と動画の冒頭・顔がよく見える後半を見比べて、肌のキメ、顔立ちと濃い点の有無を確認する。 [Flow共通テンプレート](flow-template.md)

## 冒頭の見切れを防ぐ手順

1. **新作の提案前に元画像の縦画角を確認する。** 横長の元画像は中央の9:16相当の範囲を検査し、両目・口元・装身具全体とその周りの余白を見る。新作の商品を選べるときは、中央の縦画角に収まる未使用候補を優先する。右寄り・左寄りの原本では、人物側に縦枠を寄せて必要な範囲が入る位置も確認する。確認した範囲と見切れる箇所をepisodeに記録する。
2. **Flowの開始プレビューでモードを決める。** 実際の縦9:16プレビューに両目・口元・装身具全体が余白付きで収まる場合はFramesを使う。見切れが残る場合や実プレビューを確認できない場合は、対応モデルのIngredientsに同じサイト原本を1枚指定する。Ingredientsを選んだ段階では生成動画の開始画角は未確認。確認済みのFramesからの出力でも見切れる場合はIngredientsで再確認する。指示文の前に想定モードを書く。 [Google Flowヘルプ](https://support.google.com/flow/answer/16353334?hl=ja)
3. **顔と装身具が収まった固定構図で始める。** 0秒から両目・口元全体と、元画像で見える装身具全体に余白を取る。ペンダントはチェーンが見える両側とトップの先端、片耳の耳飾りは元画像と同じ側の取り付け部から先端までを収める。カメラを固定し、全編で必要な範囲を維持する。
4. **生成後に0秒・0.5秒・1秒と顔が見える後半を確認する。** 冒頭1秒に見切れがあれば `revision_needed` とする。後半を含め、ほくろや単独の濃い点が見えるテイクも同じ扱い。再生成前に元画像と冒頭フレームを比べ、同じ切り出しが続く場合は人物を中心にした縦の開始画角と使用モードを見直す。

## 画像→動画の制作ゲート（Google公式の推奨＋SORA独自の検証方針）

[調査と一次出典](research/flow-veo-prompting-2026-11-21.md)に根拠を記録。

1. **画像プリフライト**：サイト掲載の元画像そのものを確認・提示。[冒頭の見切れを防ぐ手順](#冒頭の見切れを防ぐ手順)で使用モードを決め、装身具と手首の数を確認する。横長でも**ユーザーの明示依頼なしに縦型の派生画像を作成しない**。追加編集を頼まれた場合だけ別ファイル/別IDで記録し、商品が見切れないか確認する。
2. **動きは1つだけ**：基本は「顔に視線を向け微笑む」、ブレスレット着用腕は体の横/胸付近で静止、反対腕はフレーム外。カメラは固定か極小の動き。多段階ジェスチャーを避ける。
3. **短いプロンプト**：開始画像が示す人物・背景・衣装を延々と再説明しない。構図・微細な動き・短いセリフの3要素で十分な場合は短いプロンプトを選ぶ。
4. **一度に1変数を試す**：開始画像変更、動作変更、音声変更を同時に実施して原因を断定しない。A/Bを残し、再生成に使った正確な画像・指示・モデルを記録。
5. **失敗からの切替**：腕やアクセサリー重複が2度続けば「No duplicate」を増やすのでなく開始画像と構図を変える。発音失敗が続けば短文1行へ、なおダメなら Flow project Settings の **Return silent videos** で映像のみ生成してCapCut等で別音声を付ける。別音声ではリップシンクは別工程。
6. **声の参照**：Flowの **Omni Flash / Ingredients** で音声参照を利用できる場合がある。画像→動画のすべてのモデルで声参照可能とは扱わない。対応を画面で確認する。

## クリップと総集編

- **Flow 1本は10秒**。以前の箱根編は約60秒の1本へ編集する構想で、複数クリップを組み合わせる。60秒完成・公開の証拠がなければ完了扱いにしない。
- Flow素材は1本ずつ採点・修正。動画や再生成の完成状況は `production-status.json` に記録する。
- 後編集で日英字幕/音楽を付与し、商品ページへ誘導。外部SNSの投稿は本人が行った/投稿URLを確認した場合のみpublished。

- [ ] 元画像と冒頭・後半の顔を照合した。元の顔立ちと肌のキメを保ち、頬・口元まわり・あごに見えるほくろや単独の濃い点がない
- [ ] 0秒・0.5秒・1秒を確認した。両目・口元と元画像で見えているアクセサリーの全体が冒頭から縦画面内に収まっている
- [ ] 縦9:16、約10秒、boyfriend POV
- [ ] 日本語が正しく発音され、ネイティブらしい抑揚・口パク。単語の欠落や末尾切れがない

- [ ] Flow出力に不要な文字・音楽・追加人物がない

- [ ] 不合格なら問題と再生成指示を記録してからやり直す。同種の重複が続けば開始画像を変え、発音不良が続けば無音・別録り案に移行する

## 変更管理

明示指示による「決定変更」はこの仕様の版を上げ、エピソードで何を変えたかを記す。単一動画の特殊演出は該当episodeにだけ記録。**過去の承認済みプロンプトを、別チャットで勝手に要約/意訳しない**。
