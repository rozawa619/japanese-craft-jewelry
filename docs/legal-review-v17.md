# 法務・公開条件の再確認 — 0.17

確認日：2026-11-17。対象はSORA運営の日英工芸ジュエリー紹介サイトと、今回追加する産地地図・店舗Googleマップの表示設定。開始時の公開アプリは0.16.0（60商品・24県）です。本書は一次情報の調査と実装上の判断を記録する資料で、全商品・全法域の権利クリアや弁護士の法的認定ではありません。実装・公開で何を確認したかは[検証結果](verification.md)・[公開記録](deployment-results.json)、資料別の取得状況は[調査JSON](legal-review-v17.json)を正本とします。

## 今回の判断

- Googleが提供する通常の埋込と、閲覧者情報・Cookieの取扱いは別の問題です。地図の著作権表示を保つことだけで、すべての訪問者への無条件の自動接続が適法になるとは判断しません。
- 店舗のGoogleマップは、大きな表示枠を常設し、初回の説明と明示選択の後はページを移っても自動表示できる設計にします。地図専用の設定として期限・撤回を用意し、広告の同意や認定CMPとは区別します。未選択・拒否・期限切れではGoogleへ接続しません。
- GitHub Pagesの商用取引促進用途の制限は現在もあります。販売機能がないという理由だけで収益化サイトの用途適合を認定しません。ホスト側の確認または適切な公開先への移行、本人情報・広告アカウント・契約は、ソースだけで完了する項目ではありません。

## 1. Googleマップの埋込・帰属表示

GoogleのGeo Guidelinesは、ウェブサイトへの通常の地図埋込とテキスト/ボタンリンクを案内しています。提供されたHTMLを使用し、ロゴ・データ提供者・著作権表示を隠したり切り抜いたりしません。画像を取得して静止画として再配信する方法や、別事業者のAPI keyの転用へ広げません。独自の検索・地図機能など統合用途を増やす場合はMaps Platformの条件を別途確認します。[Google Geo Guidelines](https://about.google/brand-resource-center/products-and-services/geo-guidelines/)

既存registryの確認済みShare埋込URLを使い、外部検索・経路リンクと公式店舗案内を残します。表示幅の拡張は可能ですが、Googleの帰属や操作UIへ重ねて自前ボタンを置かず、縦横比や最小幅でも読めることを確認します。これは通常埋込に関する実装判断で、Googleから個別の承認を取得したという意味ではありません。

## 2. 常時表示と初回選択・撤回

EUの公式案内では目的により事前同意が必要なCookieがあり、必要な同意の前に設置しないこと、目的ごとの説明と容易な撤回が示されています。UK ICOの2026-04-29確定ガイダンスも、例外に当たらないstorage/accessには事前同意、第三者・目的の説明、同程度に容易な撤回を求めています。localStorageへ移せば対象外になる、ページをスクロールすれば同意した、という扱いはしません。[EU Online privacy](https://europa.eu/youreurope/business/growing/digitalising/online-privacy/index_en.htm)、[ICO consent in practice](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guidance-on-the-use-of-storage-and-access-technologies/how-do-we-manage-consent-in-practice/)

今回の保守的な実装条件は次のとおりです。全法域への適用を断定する代わりに、訪問者の国を推定せず共通のプライバシー設定を設けます。

1. 未選択ではiframe、Google画像、Google向けpreconnect等を作らない。商品や住所は読める。
2. 提供者Google、店舗の地図を表示する目的、IPアドレス等の接続情報とCookie等の可能性、Google Privacy、設定保存の期間を選択前に示す。
3. 「表示する」と「表示しない」を理解できる操作にし、あらかじめ同意を選択しない。通常の商品閲覧を同意の条件にしない。
4. 許可した場合だけ、別の商品ページ・再訪問で地図を自動表示する。設定は追跡IDを含めず、目的・版・期限が分かる最小限の値にする。30日等の期間は運営上の判断であり、法定の期限と呼ばない。
5. 地図付近とPrivacyから設定を変更でき、撤回時は全iframeを削除する。期限切れ・不正データ・保存拒否・読込例外は未許可へ戻す。保存できない場合はページ内だけの選択として説明する。
6. 同意の保存とGoogle側のデータ保持を区別する。撤回やlocalStorageの削除は、Googleへ送った情報やGoogle側Cookieを消さない。
7. 目的・受領者・条件を変えた場合は設定版を更新して再選択する。複数タブ、戻る/進む、言語切替でも撤回を尊重する。

GoogleはIP等の接続情報とCookie等を扱うこと、サービス提供・安全・改善その他の処理目的をPrivacyで説明しています。実際の地図で使われない目的まで断定せず、当サイトの設定でGoogleの全処理を管理できるとも説明しません。[Google Privacy](https://policies.google.com/privacy)

## 3. 日本の外部送信・個人情報

地図が扱う情報、送信先Google、当サイトの地図表示目的と送信先の利用目的を、地図近くと日英Privacyから確認できるようにします。情報提供メディアが外部送信規律の対象となる可能性を「個人サイト」「フォームなし」だけで除外しません。日本の通知/公表等の枠組みと、EU/UKの事前同意要件は同一ではありません。[国会会議録の政府説明](https://www.shugiin.go.jp/internet/itdb_kaigiroku.nsf/html/kaigiroku/009420820220512017.htm)

最初のブラウザー取得では総務省の案内・FAQとe-Gov本文を読めませんでした。その後、e-Gov公式v1 APIから電気通信事業法・同施行規則・特商法の現行XMLを取得し、以下の対象条文を独立して読み直しました。初回の取得失敗7件を調査JSONへ履歴として残し、後続の成功と区別します。総務省の現行FAQ、EUR-Lex本文等の未取得と、今回読めた現行の法律・省令は分けます。[公式API仕様](https://laws.e-gov.go.jp/docs/law-data-basic/8529371-law-api-v1/)・[追補の条文/取得時刻/SHA](legal-egov-followup-v17.json)

| 公式APIから再確認した範囲 | このサイトとの比較 |
| --- | --- |
| 電気通信事業法27条の12 | 対象の電気通信役務/事業者に該当する場合の外部送信について、事前の通知・容易に知り得る状態、または列挙された例外等の条件を確認。紹介サイトだから無関係と決めない |
| 施行規則22条の2の27 | 不特定の利用者による情報閲覧を目的とする役務も含まれる。実際の事業・設備・役務の要件と比較する必要があり、小規模/無広告だけを除外理由にしない |
| 同28 | 日本語・平易な表現・適切な表示と、当該ページまたは容易に到達できるページでの確認方法。現在の日英Privacyと同ページ日本語への切替・地図設定への導線を比較し、出典一覧にだけ隠さない |
| 同29 | 送信される情報の内容、情報を取り扱う者の氏名/名称、利用目的が指定事項。地図の説明とPrivacyの受領者/データ/目的をそれぞれ確認する |

API仕様は施行中の現行法令の全文取得を案内しています。今回はXML全文を取得しましたが、解釈・比較したのは上表と特商法11条の対象条文です。法令全条文の解釈や、この運営の全事業実態への適用認定ではありません。元XMLの全SHAと、法令番号を`LawFullText`内から取得したこと、対象条文が原XMLの`MainProvision`と一致することを追補へ記録しています。

Googleの参考表は確認できましたが、Mapsの個別行はなく、Analyticsの情報をMaps固有仕様に転用しません。Google公式Privacyの現在の説明は、個別通知に別段の定めがなければEEA/スイスの利用者情報はGoogle Ireland Limited、英国はGoogle LLCとし、Maps等に索引/表示される情報については地域を問わずGoogle LLCと区別しています。後者を閲覧者の通信情報すべての処理主体と混同しません。[Googleの外部送信参考情報](https://business.safety.google/intl/ja/tba-jp/)・[Google Privacyの処理主体](https://policies.google.com/privacy?hl=en)

今回の比較時点で表示は「Google」と公式Privacyリンクでした。これだけから直ちに違法と断定はしませんが、同規則29の名称により明確に合わせるため、Privacyの地図節でGoogle LLCと、地域・処理内容に応じるGoogle Ireland Limitedを識別できる説明を推奨します。Googleの一般利用規約もGoogle LLCと関係会社を区別しています。「Googleだから全処理が適法」「英国もIreland」「Mapsの全情報が一律LLC」という説明は採用しません。[Google Terms](https://policies.google.com/terms?hl=en)

公表されている作家名や事業者情報も、取扱いによって個人情報の対象です。紹介に必要な公開事業情報だけを扱い、私宅や個人の連絡先を新たに収集・掲載しません。[個人情報保護委員会FAQ](https://www.ppc.go.jp/all_faq_index/faq1-q1-5/)

## 4. 海外の適用と実在する運営情報

EEA外の運営者でも、EEAの人にサービスを向ける、行動を監視する等の場合にはGDPRの検討が必要です。英語表示だけで必ず適用/不適用と決めず、対象市場・実際のデータ処理・事業関係を確認します。適用される場合は処理主体、目的、法的根拠、保持、権利対応等の情報が必要です。地図の設定機能だけでこの全義務を満たすとはしません。[EDPB small business guide](https://www.edpb.europa.eu/sme/learn-the-basics/data-protection-basics_en)、[European Commission obligations](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/obligations_en)

公開名SORAと、契約・権利対応に必要な実情報は別です。連絡先を公開しない依頼に従って架空のメール・氏名・住所は作りません。GDPR等が実際に適用される処理では、実在する処理主体・必要な権利対応情報等は現在の運営にも必要であり、広告の有無や収益化の開始時期とは別です。「広告offだから現在は関係ない」とはしません。適用を判断する実際の対象地域・事業・処理の情報や、必要な実窓口は未提供のため、その範囲を運営者依存の未完了事項として残します。広告配信を導入する際には、さらにその配信に固有の条件を別途確認します。

## 5. アフィリエイトと広告表示

日本のステマ告示は原則として表示を決定する商品等の供給事業者を対象とし、すべてのアフィリエイターが同じ直接規制対象になるという説明はしません。共同供給の例外や別の契約責任等はあります。米国向けには金銭・無償提供等の重要な関係を分かりやすく開示するFTCの考え方も確認しました。[消費者庁Q&A](https://www.caa.go.jp/policies/policy/representation/fair_labeling/faq/stealth_marketing/)、[FTC endorsement FAQ](https://www.ftc.gov/business-guidance/resources/ftcs-endorsement-guides-what-people-are-asking)

現在の未申請・通常URLを維持し、承認時は実際のリンクより前に日英の広告開示を出す仕組みを保ちます。紹介料の有無、提供品や有料掲載の関係は事実に合わせます。AI人物を購入者・体験者・推薦者として使いません。法令上の結論と広告主の契約条件は分け、提携条件が未確認のプログラムを有効化しません。

## 6. AdSense・CMP

Googleの現行説明は、EEA/UK/スイス向けのパーソナライズ広告にGoogle認定CMP・TCFを求めています。一方、非認定CMPからのトラフィックでも非パーソナライズ/制限付き広告の対象になり得るという説明があるため、「全広告で必ず認定CMP」と一律に書き換えません。非パーソナライズでもCookie等の必要同意は別に残ります。[Google certified CMP requirements](https://support.google.com/adsense/answer/13554116?hl=en)、[Google consent setup](https://support.google.com/adsense/answer/7670013?hl=en)

現在のAdSense off・未接続を保ちます。地図設定を広告同意や認定CMPと呼びません。本文や商品数の充実、審査用の技術検査は、AdSenseの受理・合格・配信を保証しません。実アカウント、所有確認、実ID、選んだ配信方式と必要なCMP/Privacy/CSP・実情報は導入時の作業です。

## 7. 画像・文章・AI・デザインの権利

AIでも既存作品との類似性・依拠性を踏まえた利用判断が必要です。「AIイメージ」という表示は、第三者の写真や工芸デザインの使用許諾の代わりにはなりません。公式写真を転載・hotlink・生成入力へ流用せず、創作的な表現をそのまま持ち込まない現在の運用を維持します。特定の商品意匠やブランドについて世界中の登録を調べたわけではありません。[文化庁 AIと著作権](https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html)、[文化庁の生成・利用段階の説明](https://www.bunka.go.jp/seisaku/bunkashingikai/chosakuken/bunkakai/68/pdf/93906201_09.pdf)

生成記録・元PNG・採否を保持し、人物とジュエリーを実物写真や正確なSKU再現と受け取らせない説明、近くの公式実物情報へのリンクを維持します。正確な実商品写真を使う場合は権利者から用途を満たす許諾を得ます。模倣・誤認の具体的指摘があれば対象画像を外して再確認する運用が必要です。出典リンクだけで写真・独自文章の転載権を得たことにはしません。

産地の日本地図は、Google地図等のスクリーンショットを加工したものにせず、独自の模式図または利用条件を確認した地理データを使います。出典・ライセンス・必要な帰属を残し、縮尺や島の配置を省略した場合は正確な道路/経路案内図と誤認させません。

## 8. 仕様・価格・産地・ランキング

素材・部品・鋼種・片耳/一組・重量の基準を混同せず、金属アレルギーの安全保証、治療効果、未測定の着け心地、未使用レビューを追加しません。国内実参考価格と海外実価格を別市場として保ち、店頭の安さや免税・値引きを推定しません。今回の文面補助走査ではアレルギー等の注意がある箇所を確認しましたが、全商品を再採寸/再購入/試用した調査ではありません。[FTC advertising FAQ](https://www.ftc.gov/business-guidance/resources/advertising-faqs-guide-small-business)

TOP10は観光データに基づく地域の訪問指標であり、商品の売上・満足度ではありません。DISCOVERの2〜3件は編集上のピックアップで、人気の実績と呼びません。地図の色分けは掲載商品の有無を示し、県全体の工芸認証や全工程の産地を認定するものにしません。

## 9. 店舗・在庫・特商法

店舗名・住所・営業時間・行き方は公開一次情報で確認した範囲を使い、店の取扱ブランドと対象SKUの店頭在庫を分けます。地図を表示したことで現在在庫も保証されたと説明しません。私宅・事業登記だけの所在地・過去の催事を常設店と扱いません。

通信販売の説明では、販売業者等が通信手段によって契約の申込みを受ける取引が対象とされています。現在の商品紹介・外部リンクだけの機能から、当サイトを販売主体と認定する根拠は確認していません。偽の販売者情報は作りません。将来、注文・予約・有料サービス・共同供給等を行う場合は、その実態に合わせて特商法上の表示等を再判断します。[消費者庁 特商法ガイド](https://www.no-trouble.caa.go.jp/what/mailorder/)

e-Gov API追補では特商法11条も確認し、通信販売をする販売業者・役務提供事業者の広告表示の条件と比較しました。現在のSORAサイトが販売・決済・契約申込み受付を行わないという機能の確認と合わせ、架空の販売者住所等を追加しない判断を維持します。個別の広告契約や共同供給等の実態が変わる場合まで、適用除外を保証するものではありません。[対象条文の追補](legal-egov-followup-v17.json)

## 10. ホスト契約と未完了の切り分け

GitHub Pagesはオンライン事業や商取引の促進を主目的とする無料ホスティング用途を制限しています。これは現行公式にも残っています。アフィリエイト紹介だけなら必ず適合するという例外は確認できませんでした。現状を違法サイトと認定する話と、ホスト契約の用途適合は別ですが、収益化前に解消する重要項目です。[GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

今回ソース側で完了できるのは、地図の接続制御/表示/説明、広告停止と誤起動防止、独自文章・画像表示、追跡可能な根拠・検証・移行準備です。次は事実・権限・選択が必要な別項目です。

| 項目 | 必要な判断・情報 |
| --- | --- |
| ホスト用途適合 | GitHubへの適合確認、または利用条件に合うホストの選定・実アカウント・移行 |
| 収益化 | 本人が契約できる申請者情報、実プログラムの承認と契約条件、広告ID/所有確認 |
| 海外プライバシー | 実際の対象地域・処理主体・受領者・権利対応窓口等に基づく適用確認 |
| 実物写真・個別権利 | 撮影者/権利者等から必要な許諾。AI表示を許諾と数えない |
| アカウントの安全 | MFA・権限・回復・branch protection等の本人アカウント設定 |

未提供の情報を作る、実契約や承認を得たふりをする、技術チェックの成功で上表を完了にする、といった扱いはしません。[申請前の一覧](pre-application-checklist.md)と最新の残タスク台帳を更新し、今回の実装済み項目と分けて引き継ぎます。
